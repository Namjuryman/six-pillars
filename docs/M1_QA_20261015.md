### 分页修复与证据边界

`src/features/admin/data.ts` 改为 owner 过滤、唯一 UUID 升序游标、每批最多 500 条，直到**空页**才结束；服务端上限低于 500 也不会提前结束。排序后保持 created_at 最新优先，相同时间按唯一 ID 确定顺序。某页失败不返回部分成功；重复/不前进的响应直接失败。游标避免 offset 因其他设备删除行而跳过记录，但多次请求仍不是跨表事务快照；长列表仍整体保存在内存/DOM，三年个人规模可用，大规模数据需另评估服务端筛选/虚拟列表。

真实 SDK 在模拟 HTTP 层验证四表各 1,505 行、173 行服务端 cap、空/整页边界、中途拒绝、不前进响应；UI mock 在实际 Edge 中确认完整统计及筛选。**本轮未向真实开发库写入 1,505 条数据，也未重跑真实 owner/non-owner 107 项矩阵**；原 RLS 结果仅作为历史证据，下方保留。无需为了此次读取修复重新授予 QA owner 权限。
